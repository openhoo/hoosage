# Hoosage review and repairs — 2026-10-07

## Scope and process

Four agents reviewed and repaired the VS Code extension, local ingestion and
accounting, dashboard, and standalone JetBrains plugin. Independent second
passes cross-reviewed ingestion changes, shared sync, project metadata, and
collector/lifecycle behavior. Findings were reproduced with synthetic records;
no developer's real usage history was used as a fixture.

The starting checkout was clean at `b5dac04`, matching `origin/main`, with 80
passing JavaScript unit tests. Repairs live on `fix/hoosage-review-polish`.

## Repairs

| Area | Defect and repair |
| --- | --- |
| CLI accounting | Replayed shutdown/checkpoint IDs mutated cumulative baselines and costs. Deduplicate before applying counters and persist dedup state across cached restarts. |
| CLI resets | Resume/compaction counter decreases lost the first new interval; explicit zero snapshots failed to establish baselines. Recognize reset intervals and preserve measured zero baselines. |
| Session totals | Source and delimiter collisions merged unrelated sessions. Use structured project/source/session identities. |
| Transcript updates | The first incomplete metadata remained forever. Merge later measured values while retaining original attribution and excluding stale regressions. |
| Transcript precision | Growing tool rounds retained a single round's input/output as aggregate measurements. Clear values that no longer measure the whole request. |
| Transcript identities | Late model-message IDs created duplicate entries. Keep hashed aliases beside local stored calls and in transcript caches, with no added exported call fields. |
| Copied transcripts | Earlier incomplete copies masked richer later copies. Merge copies while preserving the earliest project, session and timestamp. |
| Shared sync | Identical CLI records from multiple hosts counted twice. Deduplicate request IDs across peer files and prefer newer file metadata. |
| Shared file recovery | Replacement, in-place rewrite, and partial validation could retain stale records. Check file identity and a bounded consumed-byte checkpoint; commit parsed entries only after validation. |
| Shared updates | Changed metadata for existing records was never republished. Track serialized content and restore it across restarts. |
| Shared boundaries | Reject records from another workspace, unsafe counters and invalid timestamps; cap appended files at the reader's 64 MiB limit. |
| Metadata privacy | Unexpected project fields could reach webviews and JSON exports. Restore only valid, allowlisted project metadata and exclude both local path hash sets from exports. |
| POSIX attribution | Case-folded paths could charge the wrong registered folder. Add exact local hashes, validate legacy folder URI identities, preserve project IDs/history, and reject ambiguous legacy groups. |
| Extension lifecycle | In-flight refresh/collector startup could outlive disposal. Guard subsequent work, await idempotent deactivation, and close delayed listeners. Collector closure is shared by concurrent shutdown callers. |
| Dashboard | Preserve focus across refreshes, retain a persistent announcement region, report refresh outcomes, and move focus after project drilldown. |
| Dashboard accessibility | Add Usage details navigation and named icon controls; expose chart buckets with incomplete-value labels; improve calendar pressed states, instructions, announcements and Escape behavior. |
| JetBrains scanner | Normalize equivalent paths and parse escaped, duplicate or ambiguous workspace metadata defensively. |
| JetBrains view | Coalesce scans, preserve cancellation, display recoverable errors, sort counts/costs numerically, include years in session dates and label the date filter. |

## Compatibility and verification limits

CLI and transcript cache formats rebuild older caches; usage history and project
IDs are retained. Hash aliases are local metadata and never become exported call
properties. Older POSIX workspace groups with only folded hashes require reopening
before CLI attribution is upgraded; ambiguous records remain unassigned.

Shared-file freshness uses file modification time, so peers should keep clocks
and the shared filesystem's metadata reliable. Previously shared records remain
until removed by the user, as before.

The VS Code checks use synthetic telemetry and isolated profiles. They do not
prove actual authenticated Copilot delivery, remote Chat support, billing
reconciliation, or a live installed JetBrains IDE session. These artifacts have
been built and reviewed; the PR is not a published release or an installation
into the user's normal editor profile.
